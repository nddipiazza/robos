What this is. If you keep movies and TV shows on a home server, you have probably used Plex or Jellyfin: one box holds the files, every screen in the house streams from it, and the box remembers what you watched. Until this week, RobOS did not have that box. Each RobOS computer scanned its own folders, kept its own library, and kept its own idea of what you had watched. Two laptops meant two libraries that slowly disagreed.

RobOS Media Server fixes that. You install it once on the machine that holds your files. It scans the folders, works out which files are movies, which are episodes of which show, which are albums and which are eBooks, and serves all of it over your home network. Every other RobOS machine just points at it. RobOS Movie Player and RobOS Audio Player fill themselves in from the server, start where you left off, and report back what you watched so the next screen knows too.

This post builds on the original RobOS Movie Player introduction and the Tablo DVR and Roku post. The companion post, a standalone Roku channel and Smart TV casting, covers what we built on the TV side using the same server.

1. The server: index once, stream everywhere

The server lives in packages/media-server and listens on port 19234. You organise your files into services (Movies, TV Shows, Music & Audio, Books & eBooks, Courses & Education), each pointing at one or more folders. On the server we run at home, a full scan currently reports 120 movies, 73 TV shows with 3,251 episodes, 14,654 music tracks, 1,057 books and 585 course videos, all from one GET /api/info call.

  • Understanding messy file names. lib/media-parser.js turns release-style names into a show, a season, an episode number and, when there is one, an episode title. A later fix stopped it from inventing episode titles: when nothing but quality and release tags follow S01E01 (as in Show.S01E01.1080p.WEB-DL.mkv), the episode is left without a title instead of borrowing the tags or the raw file name.
  • Streaming without converting when possible. /stream/:id serves the original file with HTTP range requests, so a player can jump anywhere in it. When a browser cannot decode a file, /transcode/:id.mp4 converts it on the fly with FFmpeg, and /hls/:id/index.m3u8 cuts it into an HLS playlist for TVs. Subtitles are served as WebVTT from /api/subtitles/:id.vtt, and cover art from /api/art/:id.jpg.
  • Books, too. lib/epub-reader.js reads EPUB chapters directly, and the server includes a simple web reader at /books/read/:id.
  • Runs without a desktop. bin/install-media-server.sh installs it as a systemd --user service (robos-media-server.service) with automatic restart, so it keeps running on a headless box after you log out.

2. Your AI agent can browse the library (MCP)

The Model Context Protocol (MCP) is a standard way for AI assistants to call tools. The server speaks it three ways: plain HTTP JSON-RPC at /mcp, server-sent events at /mcp/sse, and a stdio bridge in bin/media-server-mcp.js. Asking our home server for tools/list returns 14 tools, including robos_media_search, robos_media_list_shows, robos_media_get_show, robos_media_read_book and robos_media_continue. That means an agent can answer “which House episodes have I not seen?” or read you a chapter of a book without any extra glue code. The dispatcher lives in lib/mcp-handler.js.

3. Set it up once, and every machine follows

The connection is stored in one small file, ~/.config/robos/media-servers.json. Three pieces keep everything in step:

  • Discovery. discoverMediaServersOnLan() in robos-lib/media-service-client.js first tries hosts you already know about (saved servers, RobOS Services SSH hosts, Data Sources SFTP hosts), then knocks on port 19234 across your local /24 network, 64 addresses at a time with a 450 ms timeout each, and asks anything that answers who it is.
  • Background sync. A new robos-preferences-sync.service (preferences-service.js) runs even with no app windows open. It checks each server every 45 seconds, reacts within about 400 ms when media-servers.json changes, and only rewrites a player's library when the server's catalog revision has moved. It also registers the server's MCP endpoint with MCP Manager.
  • Config Sync. media-servers.json is now part of the RobOS Preferences group in the Config Sync backup vault. Set up the server on your desktop, sign in to the vault on a fresh laptop, and the laptop's Movie Player and Audio Player fill themselves in without you adding a single folder.

Two clean-up changes made the first run on a new machine less confusing. When a Media Server is configured, the players stop auto-importing every SFTP share from Data Sources as a separate library, so you are not looking at the same films twice. And preferences-service.js --reset-players wipes the local Movie Player and Audio Player library, caches and history files and reloads them straight from the server, which is the quickest way to get a muddled machine back to a known state. We also removed a placeholder “Lo-Fi Synth Session” track that the players used to seed into a brand-new queue (it streamed from a third-party CDN), so a first launch now opens with an empty queue and plays nothing until you ask.

4. Playback fixes: correct length, MKV without conversion, seeking while converting

Streaming from a server surfaced three bugs that a local file never showed (commit 4060b04b):

  • Every MKV was being converted. The parser assumed any .mkv needed remuxing. Now GET /api/playback-info/:id runs ffprobe and only asks for conversion when the codecs need it. Direct play is allowed for MP4, M4V, WebM, MKV and OGV containers holding H.264 (8-bit), VP8, VP9, AV1 or Theora video with AAC, MP3, Opus, Vorbis, FLAC or PCM audio (analyzePlaybackSupport() in lib/transcoder.js).
  • Converted video had no length. A live FFmpeg stream does not know how long it is, so the progress bar was useless. The same probe now returns the real duration, and transcode responses carry it in an X-Media-Duration header.
  • Seeking during conversion. If you drag to a point the player has already buffered, it simply jumps. If you drag past it, Movie Player restarts the conversion at that second (/transcode/:id.mp4?start=<seconds>) and keeps the timeline in the right place, instead of silently snapping back to zero.

A related scan fix keeps services that have not been rescanned yet visible while another one rescans, so your Movies tab no longer empties itself for a minute while 14,000 music files are being re-read.

5. Resume points and the Watch History tab

Movie Player now tracks how far into each movie and episode you got and sends it to the server (POST /api/progress, batched per server). Any other machine pulls it back with pullProgressFromMediaServers(); the newer timestamp wins, so two computers watching at once do not overwrite each other. The rules live in updateProgress() in lib/catalog-store.js: anything longer than a minute counts as Watched once you reach 92% of it, or once you are within the last 45 seconds after at least a minute of viewing, which handles end credits. Anything you started and stopped earlier is In Progress with a resume point.

Shows are summarised the same way. Each show card counts watched and in-progress episodes and points at the episode you were most recently in the middle of, so “Continue Watching” takes you to the right place even when you jump around seasons (getTrackWatchState() and friends in lib/library-index.js).

The Watch History tab (src/WatchHistoryTab.jsx) puts all of that in one skinny table. Each row has resume, start-over, mark-watched and remove actions, and the list renders in pages of 300 rows so a history of several thousand entries stays responsive. In the capture above, the filters show 2,943 entries, 6 in progress and 2,937 watched.

One smaller change is easy to miss: if you leave the Now Playing tab while a video is playing on the computer, the video now shrinks into a small live picture-in-picture slot instead of being replaced by a still thumbnail (commit 27799c5f). It is the same video element moved into a measured slot, so playback never restarts, and clicking it takes you back to the full stage.

6. Bring your history with you

Nobody wants to re-mark 3,000 episodes by hand. robos-lib/watch-history-import.js reads history exported from other tools and applies it to your RobOS library:

  • Plex watch-history JSON and raw Plex MediaContainer JSON;
  • Tautulli, Jellyfin and Trakt JSON;
  • Letterboxd, Trakt and Tautulli CSV;
  • RobOS's own portable history format (robos-media-history/1).

The hard part is matching names. Your old server may call a show Ghosts (US) while the folder on disk says Ghosts, or Stargate SG-1 versus Stargate SG1. The importer reduces both sides to a canonical key, keeps remakes from different years apart, and counts repeated plays of the same item only once per timestamp, so importing the same file twice changes nothing. Results go to Movie Player and Audio Player history and are pushed to the Media Server in one batch, so a Roku TV or another laptop sees them straight away. You can drop a .json or .csv file on the Watch History tab, click Import History…, or use the CLI.

7. Watchlist and “where we are” by voice, CLI and MCP

The new movie-watchlist skill gives the same five operations to every front end: list the watchlist, add, remove, mark a show (or one season) as new, and set the current episode. The last one is the useful one for couples and families. Saying “our current episode of Severance is season 2 episode 4” marks everything before S02E04 as watched and S02E04 onwards as unwatched, so Continue Watching lands exactly there. The episode can be given as S02E04, 2x04, “season two episode four”, “season 3” (meaning its first episode) or an episode title (parseEpisodeSpec() in robos-lib/media-history.js).

The same phrases work through the RobOS Voice desktop assistant and the Home Speaker router (nabu-command-router.js), through robos-movie-watchlist on the command line, and through Movie Player's own MCP server (bin/media-mcp.js, with tools such as robos_media_watchlist_add, robos_media_set_current_episode and robos_media_import_watch_history). The last commit in this batch added random picks (“play a random unwatched episode of House”, “play a random 90s movie”) and the ability to name a Smart TV in any of these phrases; the companion post covers how those reach the TV.
