What this is. Most people watch TV with the remote that came with it, not a laptop. Our earlier work, described in the Movie Player introduction and the Tablo DVR and Roku post, already put a RobOS channel on a Roku TV, but it depended on a RobOS desktop staying awake to feed it. Close the laptop lid and the TV lost its library.

The new RobOS Media Server, introduced in the companion post RobOS Media Server and Watch History, is always on. So the TV now talks to it directly. You get a Roku channel that behaves like a normal streaming app: pick a show with the remote, it resumes where you stopped, and the next laptop or phone you pick up knows how far you got. And because the server is always on, it can also act as the “remote” when you say “play a random episode of House on the Roku TV” to a speaker or a phone.

1. The standalone channel

One command builds and installs it on a Roku in developer mode:

./packages/robos-cli/robos-tv install-movie-player --ip <roku-ip> --server http://192.0.2.10:19234

installRokuMoviePlayer() in robos-lib/tv-engine.js does four things. It reads the server address from media-servers.json if you leave out --server. It downloads the server's grouped library from GET /api/roku-cinema, where every TV show arrives as one card with its seasons, episodes and watch counts inside. It writes a SceneGraph channel package with that library baked in, so the first screen appears instantly. Then it sideloads the package and opens it.

After that, the channel keeps itself current by polling the server. It sends the library revision it already has (?knownRev=), and the server only sends a full library when something changed. On our home server the full feed for 120 movies and 73 grouped shows is 1.77 MB; the “nothing changed” reply is 60 bytes. While a video plays, the channel reports its position to /api/tv-progress, and when an episode finishes it marks it watched, so the Watch History tab on any computer updates without the computer being involved.

The server side lives in packages/media-server/server.js and getRokuCinemaLibrary() in lib/catalog-store.js. Older formats that Roku cannot play directly (.avi, .wmv, .flv, .mpg, .ts and similar) are sent as HLS from /hls/:id/index.m3u8. Everything else plays from the original file, and if the Roku reports an error on a direct stream, the channel retries once with the HLS version before giving up.

2. A real logo on the Home Screen

The first build of the channel drew its own tile pixel by pixel in Node.js: a gold film frame with a play button, encoded as PNG with nothing but zlib. That still exists as a fallback. Commit e0c6829d replaced it with the official logo: the build runs FFmpeg on robos-transparent-background.png from the repository root, fits it onto a white canvas at each size Roku needs (540×405, 290×218 and 214×144 for the tiles, 1920×1080 for the splash), and adds a thin cyan bar at the top and a dark navy bar at the bottom. The manifest sets splash_color=#0B1120 and splash_min_time=350 so the splash does not flash past. Asking our TV which channels are installed (GET /query/apps on its control port) lists the sideloaded channel as dev, version 2.1.2, which matches the manifest's 2 / 1 / 2 version fields.

3. Casting from a server with no screen

Before, “play House on the Roku TV” only worked if the Movie Player window was open somewhere, because Movie Player did the casting. The new robos-lib/headless-tv-cast.js does it without any window. The voice router uses it when ROBOS_HEADLESS=1 is set, or when it runs on Linux with no display, which is exactly the situation on a media server in a closet.

  • Picking what to play. playTracksHeadless() builds the stream address for the chosen episode or movie, looks up where you stopped last time (anything over 5 seconds counts as a resume point), records the play in your history, and saves a small session file with the queue (up to 50 items) so “next episode” and “previous episode” work afterwards.
  • Telling the TV. The cast is posted to /api/roku-cast on every configured Media Server. The channel picks it up on its next poll, which it does twice a second while a cast is active.
  • Waking the TV. Through Roku's External Control Protocol (ECP) on port 8060, the caster sends PowerOn and launches the channel if something else is on screen. If the screensaver is showing, it sends PowerOn and a harmless keypress to dismiss it (commit 7db080fa). Two seconds later a watchdog checks again; if the TV is still on the screensaver, paused, closed, or only playing the channel's 60-second keep-alive clip, it goes Home and relaunches the channel so the new cast loads.
  • Replacing a paused cast. Starting something new while an older cast sat paused used to leave the old one stuck on screen. The channel now clears the old video before loading the new one and ignores player state changes while the switch is happening.

4. Pause, resume, and the remote in your hand

Two control paths now have to agree: voice commands going through the server, and the physical Roku remote. Commits 5986b84a and 7cdb3ed9 sorted out the conflicts:

  • Plain phrasing. “Pause the Roku TV”, “resume the Roku TV” and “stop the Roku TV” now work, not only “pause on the Roku TV”. Speech-to-text often hears “paused” or “resumed”, so those are accepted too. The rest of the sentence has to match a paired TV closely (a match score of at least 115), so “pause the music” still goes to the music player.
  • Pause is a one-time instruction. Each voice pause or resume now carries a fresh pauseKey. The channel acts on a key once and then forgets it. Previously the server kept saying “paused” on every poll, so pressing Play on the real remote was undone a second later.
  • Belt and braces. After a voice pause or resume, the caster reads the TV's own player state over ECP and sends a Play keypress if the TV did not follow.
  • The remote works as you expect. During a cast, the video keeps focus, Play or OK toggles pause, Right or Fast-forward skips 15 seconds, Left or Rewind goes back 15, and Instant Replay goes back 10.
  • Browsing on the TV wins. If you press Back and start something else with the remote, the channel calls /api/roku-cast-clear so the server forgets the remote cast and does not pull you back into it on the next poll.

5. A Default Smart TV, and one-tap commands on the phone

With several TVs in a house, saying “on the Roku TV” every time gets old. Commit 5ab95bbe adds a Default Smart TV, stored as defaultTvId and defaultTvIp in ~/.config/robos/tv-studio.json; Smart TV Studio keeps those two keys when it rewrites that file. You can set it with the star button above, by voice (“set my default TV to Roku TV”, “what is my default TV?”, “clear my default TV”), with robos-movie-watchlist set-default-tv, or through the MCP tools robos_media_get_default_tv and robos_media_set_default_tv. After that, “play Atypical season 2 episode 2” goes to that TV without naming it.

The RobOS Assistant Android app also got a scrolling row of Cinema quick commands on its server screen (commit 2ff91c6f): a random House episode, a random unwatched House episode, continue Ghosts, a random 90s movie, read the watchlist, list Smart TVs, pause, next episode and stop casting. Most of the same buttons appear on the small web page the app serves on the local network. Each one sends the same sentence you could have spoken, so the phone is just a shortcut to the voice router.

6. Two speech recognition fixes from real use

  • Split words. Speech-to-text heard “Atypical” as “a typical”, which matched nothing. Show and title matching now also compares both sides with spaces removed, and accepts a close fuzzy match on those collapsed forms (Jaro-Winkler similarity of 0.89 or more). “Put” and “throw on” were added as ways to say “play”.
  • Cutting people off. On the Android assistant, the voice detector ended an utterance after 420 ms of silence, so a natural pause after “Commander,” split one request into two. The default is now 1,050 ms with 400 ms of pre-roll, and phones still on the old 420 ms setting are migrated automatically (Model.kt).
