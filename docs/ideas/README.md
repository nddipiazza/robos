# Feature Ideas & Knowledgebase

Welcome to the RobOS Feature Knowledgebase! This directory stores raw project ideas, structured feature specifications, and implementation plans.

1. **Inbox / Raw Ideas (`docs/ideas/inbox/`)**: Dump quick notes, bullet points, audio transcripts, or rough thoughts here.
2. **Refined Feature Specs (`docs/ideas/specs/`)**: Agents refine raw ideas into structured specifications with C4 architecture diagrams, BDD Gherkin scenarios, and Knowledge Graph impacts using the `create-feature-spec` skill.
3. **Task Workflows & Epics (`docs/project-plan/`)**: Specifications graduate into executable task workflows and development epics.
4. **Autonomous Execution & Proof**: Community runners execute the workflow using isolated agent sandboxes, generating containerized test results and 1080p narrated video proofs-of-work.

## Directory Structure

- `inbox/`: Storage for quick notes, raw text dumps, and unformatted thoughts.
- `specs/`: Detailed, standardized architectural `.md` specifications generated by AI agents.

## Prompt-Driven Open Source: Community Runner Workflows

> **"RobOS changes how open source works: we just create task workflows we want to run, and ask someone in the community (or their autonomous AI agent) to run them for us!"**

### 1. Author a Feature Specification Prompt
To author a new feature spec from an idea or inbox note:
```text
You are a Lead System Architect for RobOS. Run the `create-feature-spec` skill for:
"<IDEA_CONCEPT_OR_INBOX_PATH>"
Produce a complete specification in `docs/ideas/specs/<spec-slug>.md` with C4 diagrams, Knowledge Graph impact, BDD scenarios, and an E2E verification plan.
```

### 2. Community Runner Execution Prompt
To pick up an existing spec and implement it:
```text
You are an autonomous RobOS Engineer. Implement `docs/ideas/specs/<spec-slug>.md`.
Follow AGENTS.md: branch `feat/<spec-slug>`, implement across `packages/`, update `.robos/kgraphs/`, register icons in `packages/robos-icons/index.js`, assign snapshot ports in `packages/robos-lib/snapshot-cli.js`, and add E2E tests in `packages/robos-test/tests/`.
```

### 3. Verification & Video Proof-of-Work Prompt
To verify your work before opening a PR:
```text
Run `./scripts/e2e-container.sh` to execute the E2E verification suite inside Docker with Xvfb.
Record a 1080p narrated video walkthrough proof using the `record-demo` skill.
Run `kgraph-diff` to verify zero unexpected schema drift before submitting your pull request.
```

For the complete guide on contributing using RobOS, see [**CONTRIBUTING.md**](../../CONTRIBUTING.md).
