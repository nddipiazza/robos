Guide · for a solo developer

Build apps on your own

You are the planner, the reviewer and the person who merges. The agent writes the code. This guide takes one task from a sentence to a merged pull request, then shows you how to keep going.

Before you start

  • RobOS installed, or a clone of the RobOS repository you can run apps from. See Get started.
  • gh installed and signed in (gh auth login), with the gh copilot extension for planning.
  • claude installed and signed in. Task Implementer uses no other agent.
  • Optional: codex on your PATH, for the review window's walkthrough and evidence agents.
  • A GitHub repository for the app, cloned on this machine.

Starting a brand-new app? Create the repository on GitHub with a first commit so it has a main branch, and clone it. Then either make the first task you plan "scaffold the project", or generate a starter project with the App Wizard and commit it before you plan the features.

Step 1: Connect your repository

Task Planner and Task Implementer read and write issues on a task server. For a solo project, that is your GitHub repository.

  1. Open RobOS Task Servers and click the plus button.
  2. Choose GitHub Issues. Leave the API URL blank for github.com, tick Use Git client account to use your gh login, and add your repository as an owner and repository pair.
  3. Click Test Connection. The entry is saved to ~/.config/robos/settings.json.

The apps use the first server in the list unless active_task_server in that file names another one. The active server appears in the top right of Task Planner and Task Implementer. Details: Task Servers.

Step 2: Plan the work in Task Planner

Task Planner's window is titled Task Explorer. Open it from the app launcher, or with scripts/dev-launch.sh task-planner from a RobOS clone.

  1. Create a project in the Projects list, or pick one, and click + Plan New Feature. Fill in the tech stack and architecture context. This is the background the agent plans against, so write what you would tell a new developer.
  2. Describe the feature in the prompt box and click Generate with AI, or choose a template from the chips above it. Browse All Templates opens the full library.
  3. If the agent asks follow-up questions, answer them and click Generate Epics & Tasks.
  4. Read every task. Each one should be small enough for one branch and have acceptance criteria you could check yourself. Edit the text, add or remove tasks with + Add Task, and change the persona on any task.
  5. Click Save to Project to keep the plan, then Sync All to Server to create the issues. On GitHub each issue gets a role:<persona> label and the persona's directives in its body. GitHub issues are created without links between them, so note which tasks have to be done first.

Generation runs gh copilot and gives up after 3 minutes. More on templates, personas and KGraph project plans: Task Planner.

Step 3: Implement a task in Task Implementer

The agent works in the folder Task Implementer was started from. You do not pick the folder in the window, so start the app from your repository's clone:

cd ~/src/my-app
~/robos/scripts/dev-launch.sh task-implementer

Replace the paths with your clone and your RobOS checkout. If you open the app from the launcher instead, name the clone's full path in the extra-context box so the agent knows where to work.

  1. In the Tasks tab, choose Open and select the task. Start with one that does not depend on another. Task Implementer shows no links between GitHub issues, so follow the order from your plan.
  2. Check the persona in the header. It comes from the issue's role: label. Directives shows the guidance the agent gets for that persona, and you can edit it for this run.
  3. Add hints in the extra-context box: files to look at, commands that run the tests, things not to touch.
  4. Click Start Agent and watch Agent Output. The agent creates codex/<task-key>, makes the change, runs the tests, commits and pushes. It does not open a pull request. Stop ends it.

The agent runs with --dangerously-skip-permissions as your user, with no sandbox. Run one agent per clone at a time: two agents in the same folder share one working tree.

Step 4: Review the branch before it becomes a PR

When the agent has finished, click Review branch… and choose your clone. RobOS writes a review manifest under ~/.robos/local-reviews/ and opens the review window on the branch. The diff is the branch against the remote's default branch. Uncommitted changes are not part of it.

Changes

Read the diff file by file and tick Viewed as you go. When something should change, click Suggest changes and say so in plain language, for example "remove the comments that only restate the code". The agent edits the checkout, runs the tests, commits, and the diff reloads.

Evidence

The Evidence tab shows before and after results captured at one commit. When a newer commit lands, the old evidence is marked stale, so ask for fresh evidence after every change you request. If the task has no evidence bundle, the tab says so.

Walkthrough

Click Start. An agent demonstrates the change one checkpoint at a time and pauses, so you can try it yourself. Send a message at any checkpoint to ask for a change. How it used to work, in the More menu, runs the same checkpoints on main in a separate checkout. Finishing the walkthrough does not approve or merge anything.

The walkthrough needs codex. Every tab is described in PR Review Theater.

Step 5: Open the pull request and get CI green

  1. Open the Description tab. Edit with agent drafts the description from the diff and the evidence; edit it until it says what changed and how you checked it.
  2. Open the Pull Request tab, check the title and click Create PR. Tick Create as draft if you want CI to run before you call it ready. RobOS pushes the branch head, then runs gh pr create.
  3. Watch the CI banner. Refresh CI reads the checks again. If CI fails, Get CI back to green starts an agent repair in an isolated checkout; you review its fix and push it yourself.
  4. For a draft, click Move PR to Ready once CI has passed. RobOS refuses while CI is red.

Create PR refuses when the clone has uncommitted changes (the Resolve uncommitted changes button asks the agent to deal with them), when the branch is main, or when origin is not the repository in the review.

Step 6: Merge and plan the next task

Merge the pull request on GitHub; the review window has no merge button. If your branch protection requires an approving review, that needs a second GitHub account, so for a solo repository leave that rule off or follow the team guide.

Then go back to Task Implementer for the next task. Pull main into your clone first, so the next branch starts from the merged code. If something broke after the merge, or the review turned up work for later, file it from Task Planner as a new task and the loop starts again.

Tips and fixes

Keep the agent on track

  • Small tasks review faster and fail less. If a task touches many unrelated files, split it in Task Planner before you start the agent.
  • Acceptance criteria are what you check in review, so make them concrete: inputs, expected results, error cases.
  • If the same advice goes into every run, put it in the persona's directives with Agent Personas instead of the extra-context box. Personas are saved in ~/.config/robos/agent-personas.json.

When something does not work

Open Task Servers instead of a task listNo task server is configured. Do Step 1.
Generate with AI fails or times outCheck that gh copilot runs in a terminal. Generation gives up after 3 minutes; try a shorter prompt.
The agent changed the wrong folderTask Implementer was started somewhere else. Start it from your clone, as in Step 3.
Review branch… says to waitThe agent for that task is still running. Wait for it, or click Stop.
