# RobOS — What We Built

RobOS is an AI-powered Software Development Lifecycle Operating System. It is a customised Ubuntu Linux desktop whose entire user experience is purpose-built around the daily workflow of software engineers, engineering managers, and code reviewers. Every app, panel shortcut, and AI interaction exists to move tickets through the SDLC faster and with higher quality.

---

## 1. The Operating System Foundation

### Base Stack
| Layer | Choice | Reason |
|---|---|---|
| Base OS | Ubuntu 22.04 LTS (cloud image) | Stable, cloud-init support, wide package ecosystem |
| Window manager | Openbox | Lightweight, fully scriptable, no GNOME bloat |
| Panel | tint2 | Minimal taskbar, supports launchers + executor widgets |
| Login | LightDM + lightdm-gtk-greeter | Fast, configurable, XFCE-friendly |
| Terminal | Tilix | Tiling terminal, dark theme, zsh support |
| Shell | zsh + oh-my-zsh (robbyrussell) | Developer-friendly, plugin ecosystem |
| Theme | Custom "RobOS" dark navy / cyan | Applied to Openbox frames, GTK3, tint2, tilix |

### VM / Provisioning
RobOS runs as a QEMU/KVM virtual machine provisioned with **cloud-init**:

- **Image**: Ubuntu 22.04 cloud image extended with a custom 20 GB disk
- **cloud-init user-data**: generated by `infra/desktop/gen-userdata.py` — embeds all desktop config files, splash scripts, and install steps into a single YAML at build time
- **Boot**: QEMU with KVM acceleration (`-enable-kvm -cpu host`), GTK display when `$DISPLAY` is set, SDL fallback
- **SSH**: port `2222` forwarded to VM port `22` for remote management
- **VNC**: port `5910` available for headless sessions
- **Scripts**: `infra/desktop/build.sh` builds the disk, `infra/desktop/run.sh` starts the VM

## 2. First-Boot Installation Splash Screen

One of the earliest user-experience problems: when the VM first boots, cloud-init spends several minutes installing packages. The user sitting at the login screen sees... nothing. No indication that anything is happening, no reason to wait.

### The Fix — Two-Phase Splash

**Phase 1 — `bootcmd` (fires before packages install)**

`bootcmd` in cloud-init runs at the very start of every boot, before `packages:` are installed and before `runcmd` runs. We added a single `cloud-init-per once` entry that:

1. Switches the console to `tty1` (`chvt 1`)
2. Launches a background `while` loop that every 2 seconds clears the screen and re-prints:
   - The full RobOS ASCII block-character logo (rendered inline with Unicode box-drawing characters)
   - `"AI-Powered SDLC Operating System"`
   - `"Installing packages, please wait..."`
3. Writes its PID to `/tmp/robos-splash-pid`
4. The loop exits as soon as `/tmp/robos-install-done` exists

This means the **very first thing the user sees** after power-on is the RobOS logo — before a single package has been downloaded.

```yaml
bootcmd:
  - [ cloud-init-per, once, robos-splash, sh, -c,
      "chvt 1 2>/dev/null;
       (while ! [ -f /tmp/robos-install-done ]; do
         printf '\033c\n\n\n     ██████╗  ██████╗ ...\n\n
                 AI-Powered SDLC Operating System\n\n
                 Installing packages, please wait...\n' >/dev/tty1 2>&1
         sleep 2
       done) & echo $! > /tmp/robos-splash-pid" ]
```

**Phase 2 — `install_splash.py` (runs during `runcmd`, shows progress)**

Once `runcmd` begins (after packages are installed), it kills the Phase 1 loop and launches `packages/desktop-shell/install-splash/install_splash.py` on `tty1`. This Python script:

- Renders the same ASCII logo in **cyan ANSI colour** using `\033[96m`
- Shows a **full step checklist** with `✓` (done), `▶ installing…` (current), `·` (pending) for all 8 install phases:
  1. Base system
  2. Display manager
  3. Shell (zsh + oh-my-zsh)
  4. GitHub CLI
  5. VS Code
  6. Google Chrome
  7. Plymouth boot theme
  8. Finalising
- Reads `/tmp/robos-install-status` (written by runcmd at each step) to know which step is active
- Exits when `/tmp/robos-install-done` is created

The key insight: `bootcmd` fires early enough that the logo appears **before any package download starts**, so there is never a blank or confusing screen.

## 3. Desktop Applications

All RobOS apps are **Electron applications** written in TypeScript/JavaScript, deployed to `/usr/local/share/robos/<app-name>/` and launched via `.desktop` files in `/usr/local/share/applications/`. They all require the flags `--no-sandbox --disable-gpu --disable-dev-shm-usage` for correct rendering inside the QEMU VM.

The tint2 panel at the bottom of the screen contains launcher icons for the most-used apps.

### App Launcher (`packages/app-launcher`)
The central hub for opening any RobOS app. Shows a searchable grid of all installed RobOS applications with icons. Keyboard-navigable. Triggered from the tint2 panel.

### Dev Central (`packages/dev-central`)
Daily developer status dashboard. Shows:
- Active sprint tickets (from GitHub Issues)
- PR health (open PRs, review lag, stale branches)
- Upcoming meetings / calendar events
- AI-generated daily standup summary
- Quick links to frequently used apps

### Issue Manager (`packages/issue-manager`)
Full GitHub Issues browser and workflow tool:
- Multi-tracker support (multiple GitHub orgs/repos)
- Swim lane board view (To Do / In Progress / In Review / Done)
- Issue detail with AI context, acceptance criteria, labels
- Transition issues through workflow states
- AI breakdown: converts an issue into sub-tasks with context steps
- Copilot session viewer: see what AI agents are doing on each issue

### Git Projects (`packages/git-projects`)
Local repository management and developer environment setup:
- Add/clone GitHub repositories
- Per-project **Dev Setup**: AI-generated or manually written scripts for setup, start, test, and E2E
- Scripts stored at `~/.config/robos/git-projects/{projectId}/` with `.idea/runConfigurations/` and `.vscode/launch.json` auto-generated
- **Run in Terminal**: executes scripts directly against the cloned repo
- **Run in IntelliJ**: sends scripts to the RobOS IntelliJ plugin via its IPC HTTP server; launches IntelliJ if not running and waits up to 3 minutes for the plugin to become ready
- Monaco editor for all scripts (syntax highlighting, refinement)
- AI script generation from repo README + structure
- Git log and branch browser

### IDE Manager (`packages/ide-manager`)
Manages JetBrains and other IDEs:
- Detects installed IDEs (IntelliJ IDEA, WebStorm, PyCharm, GoLand, Rider, CLion)
- Installs/uninstalls the RobOS IntelliJ plugin into the correct JetBrains plugin directory (`~/.local/share/JetBrains/<Product>/`)
- Handles IDE shutdown before plugin installation (targets `/opt/idea` processes)
- Shows plugin version from ZIP filename in a clean banner

### Workspace Manager (`packages/workspace-manager`)
Manages virtual desktop workspaces:
- Creates and names virtual desktops
- Associates a desktop with a Jira/GitHub ticket
- Tracks which apps are open in which workspace

### Lang Manager (`packages/lang-manager`)
Programming language version management:
- Install/remove language runtimes (Node.js via nvm, Python via pyenv, Java, Go, Rust)
- Switch active versions per-project or globally

### Agents Manager (`packages/agents-manager`)
Manage GitHub Copilot CLI agent sessions:
- Start, stop, and monitor running Copilot CLI sessions
- View session logs in real time
- Attach to existing sessions

### Context Manager (`packages/context-manager`)
Manage AI context sources for agent prompts:
- Define context sources (files, URLs, GitHub repos, Jira tickets)
- Organise into named context sets
- Inject context into Copilot CLI sessions

### Tech Workbench (`packages/tech-workbench`)
Technical Problem Solution Workbench (TPS):
- Create and track technical spike tickets
- AI-assisted research and solution drafting
- Link findings back to GitHub issues

### Work Journal (`packages/work-journal`)
Git-backed personal developer journal:
- Daily entries with AI-generated activity feed from GitHub/Jira events
- Archive and search past entries
- Auto-save

### Pass Manager (`packages/pass-manager`)
GUI for the `pass` password-store:
- Browse and copy secrets
- GPG-encrypted, unlocked once per day via a "daily unlock" flow
- Integrates with RobOS token/credential system

### People Directory (`packages/people-directory`)
Team directory:
- Browse team members, roles, contact info
- Linked to GitHub usernames

### Group Dev Settings (`packages/group-dev-settings`)
Shared developer settings across a team:
- Common linting rules, code style preferences
- Environment variable templates

### RobOS Preferences (`packages/robos-preferences`)
System-wide RobOS settings:
- Jira server URL / credentials
- GitHub token
- AI model preferences
- Notification settings

### File Explorer (`packages/file-explorer`)
Dark-themed file browser:
- Tree navigation
- Triggered from other apps (Git Projects, Workspace Manager)
- Receives navigation events via a mailbox file (`~/.config/robos/file-explorer-nav.json`)

### Notifications App (`packages/notifications`)
View and manage all system and agent notifications:
- Full notification history
- Filter by severity, app, date

### Toast Daemon (`packages/robos-toast`)
System-wide toast notification daemon:
- Receives events from all RobOS apps
- Shows GNOME-style overlay toasts with action buttons
- Persistent for `urgent` severity; auto-dismiss for `info`
- Notification categories: PR review needed, issue reported, blocker detected, meeting approaching, standup time, daily stats ready, sprint ticket assigned

### Security Setup (`packages/security-setup`)
First-run security initialisation:
- GPG key generation for `pass`
- SSH key setup

### Search Index (`packages/search-index`)
File system search index manager:
- Indexes local repositories for fuzzy `@`-search in AI textarea components
- Used by Issue Manager, Context Manager, and other AI-enabled apps

## 5. RobOS IntelliJ Plugin (`packages/robos-intellij-plugin`)

A fork of `intellij-community` with all RobOS additions under `platform/robos/`. Nothing in the upstream platform is modified — RobOS registers through standard extension points, keeping the fork rebasing-clean.

### IPC HTTP Server (port 63343)
A Netty-based HTTP server started at IDE launch by `RobosStartupActivity`. Accepts JSON requests:

| Method | Endpoint | What it does |
|---|---|---|
| `GET` | `/robos/health` | Returns `{"ok":true,"version":"..."}` |
| `GET` | `/robos/status` | Returns current workspace state |
| `POST` | `/robos/open-project` | Opens a directory as a project in the IDE |
| `POST` | `/robos/open-file` | Opens a file in the editor |
| `POST` | `/robos/navigate` | Navigates to file:line:column |
| `POST` | `/robos/run` | Executes a named run configuration |
| `POST` | `/robos/stop` | Stops the currently running configuration |
| `POST` | `/robos/notify` | Shows a balloon notification in the IDE |
| `POST` | `/robos/workspace` | Updates ticket/branch/collaborator metadata |

### Plugin Installation Path
On Linux, IntelliJ loads plugins from:
```
~/.local/share/JetBrains/IdeaIC<Version>/
```
(direct subdirectory — **no** `plugins/` subdirectory). `~/.config/JetBrains/` is settings-only.

### Workspace Side Panel
`RobosToolWindowFactory` adds a "RobOS" tool window showing the active ticket context, branch, and collaborators.

## 6. How Apps Are Deployed

During VM build (`infra/desktop/cloud-init/user-data` `runcmd`):

1. Node.js and npm/pnpm are installed
2. Each app package is copied to `/usr/local/share/robos/<app>/`
3. `npm install` or `pnpm install` is run in each app directory
4. A shell wrapper at `/usr/local/bin/<app>` launches the app with the required Electron flags
5. A `.desktop` file is placed in `/usr/local/share/applications/` for the tint2 launcher

All Electron apps require these flags in the QEMU VM:
```
--no-sandbox --disable-gpu --disable-dev-shm-usage
```
`--disable-dev-shm-usage` is critical — without it renderer windows appear blank (the shared memory device is too small in the VM).

## 7. Key Technical Decisions & Gotchas

### cloud-init
- `bootcmd` fires before `packages:` and before `runcmd` — use it for anything that must be visible immediately
- `write_files` does NOT create parent directories — always add `mkdir -p` in `runcmd`
- `runcmd` runs in multi-user.target (not graphical) — LightDM won't start until the next reboot
- cloud-init only runs once per `instance-id`; to re-provision, start from a fresh disk copy

### IntelliJ plugin
- `pgrep -f 'idea'` will match scripts whose path contains "idea" — use `pgrep -f '/opt/idea'` to target only the JVM
- Shell variables like `$(...)` and `${VAR}` inside a JavaScript template literal must be escaped as `\$(...)` and `\${VAR}` or JavaScript will try to interpolate them

### Electron in QEMU
- `pkill` / `killall` are blocked in the build environment — use `kill <PID>` with explicit numeric PIDs
- Killing the main Electron process (node) is sufficient; child processes (zygote, GPU) terminate automatically
- Apps must be launched with `DISPLAY=:0` when started from SSH sessions

### Pass / GPG
- GPG key must be initialised before `pass init` — `security-setup` handles this on first run
- `pass` stores are at `~/.password-store/`; the daily unlock flow decrypts once and caches the passphrase in the agent for the session
