Physical push keys

RobOS Hardware Keys connects physical FIDO2 and U2F authenticators—such as the YubiKey 5 Series, Security Key C NFC, SoloKey, and Nitrokey—directly to your Linux desktop, SSH keys, Git commits, sudo prompts, and the RobOS Pass Store. Private keys stay locked inside the hardware token's secure element and require a physical finger press on the capacitive gold contact before any signature is produced.

Architecture

RobOS Hardware Keys combines three local Linux inspection layers—/sys/class/hidraw udev attributes, YubiKey Manager (ykman), and direct python3-fido2 CTAP2/CTAP1 HID frames—so every hardware capability can be inspected and exercised without cloud services or browser extensions.

1. Hardware Inspector

When you open RobOS Hardware Keys or plug a key into USB, the Hardware Inspector tab queries the device and displays:

  • Model & Firmware: Decodes both the ykman descriptor and the integer CTAP2 firmware version (for example, 329473 → 0x050701 → 5.7.1).
  • FIDO2 AAGUID Lookup: Formats the 16-byte Authenticator Attestation GUID (such as e77e3c64-05e3-428b-8824-0cbeb04b829d) and matches it against known Yubico, SoloKeys, Nitrokey, and Titan hardware profiles.
  • COSE Algorithms & Extensions: Lists hardware-supported public-key algorithms (ES256 / ECDSA P-256, EdDSA / Ed25519, ES384 / ECDSA P-384) alongside CTAP2 extensions (credProtect, hmac-secret, largeBlobKey, credBlob, minPinLength).
  • Linux /dev/hidraw Permissions: Confirms that systemd-logind / udev ACLs grant read+write access (crw-rw----+) to your desktop user so FIDO2 operations never require running Electron as root.

2. Physical Touch Tester

Switch to Physical Touch Tester (or click ● Test Physical Push in the top bar) to run a live challenge-response against your key:

  1. Set an optional Relying Party ID (defaults to robos.local) and optional FIDO2 PIN.
  2. Click 👆 Start Physical Touch Challenge. The app generates a 32-byte random nonce, hashes it with SHA-256, and sends a CTAP2 request to /dev/hidraw0.
  3. Touch the flashing gold contact on your physical YubiKey.
  4. The right-hand Cryptographic Assertion Proof panel displays the measured touch latency (ms), protocol used (FIDO2 / CTAP2 or FIDO U2F / CTAP1), COSE algorithm, UP/UV flags, and raw signature bytes.

3. Hardware-Backed FIDO2 SSH Keys (-sk)

Standard SSH private keys (~/.ssh/id_ed25519) sit as files on disk that could be copied if a workstation is compromised. With OpenSSH FIDO2 keys (ed25519-sk and ecdsa-sk), the private key file in ~/.ssh/id_ed25519_sk contains only an encrypted key handle that is useless without your physical YubiKey attached.

  • Require Physical Touch (Default): Every ssh login, scp transfer, or git commit -S blinks the YubiKey LED and waits for your finger touch.
  • Require FIDO2 PIN (verify-required): Adds user verification (UV=1) so OpenSSH prompts for your FIDO2 PIN in addition to your physical touch.
  • Resident Key (-O resident): Stores the credential inside one of the YubiKey's 100 discoverable slots so you can run ssh-add -K or ssh-keygen -K on any new RobOS machine to pull the key stub straight from the key.
  • Live SSHSIG Verification: Click 👆 Sign Test next to any key in the list to sign a test payload via ssh-keygen -Y sign -n robos.auth and inspect the resulting -----BEGIN SSH SIGNATURE----- block.

4. FIDO2 PIN & Resident Passkeys

The FIDO2 PIN & Passkeys tab wraps ykman fido for managing on-device credentials:

  • Set or Change PIN: Configures an initial FIDO2 PIN (minimum 4 characters, up to 63 characters) or rotates an existing PIN via ykman fido access change-pin.
  • Remaining Slot Counter: Displays exact remaining discoverable credential slots reported by CTAP2 remaining_disc_creds (100 slots on YubiKey Firmware 5.7+).
  • Inspect & Prune Passkeys: Enter your FIDO2 PIN and click Load Passkeys to list every discoverable credential by Relying Party ID, username, and credential ID, with a one-click Delete action to reclaim slots.

5. Linux PAM U2F & RobOS Push-to-Approve Guards

The PAM & RobOS Guard tab integrates your YubiKey with OS-level authentication and RobOS security policies:

  1. Enroll Linux PAM U2F (pamu2fcfg): Clicking 👆 Enroll YubiKey with pamu2fcfg prompts you to touch your YubiKey and writes the resulting U2F key handle to ~/.config/Yubico/u2f_keys (mode 0600). Add the provided snippet to /etc/pam.d/sudo or /etc/pam.d/gdm-password: 
    auth sufficient pam_u2f.so cue [cue_prompt=Touch your YubiKey to approve]
  2. Git Hardware SSH Commit Signing: Clicking Configure Git Signing Now sets: 
    git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519_sk.pub
git config --global commit.gpgsign true
    Every git commit then requires a physical touch on your YubiKey and produces a GitHub-verified SSHSIG commit signature.
  3. Auto-Lock Pass Store on Unplug: When Auto-Lock Pass Store on Unplug is enabled, the background USB hotplug watcher immediately runs gpgconf --kill gpg-agent the moment your YubiKey is unplugged from USB—clearing cached passphrases from memory.
