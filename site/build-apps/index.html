Build apps

Plan it, let an agent build it, review it yourself

Three RobOS apps take a task from an idea to a reviewed pull request.

Task Planner turns what you want into issues with acceptance criteria. Task Implementer runs a coding agent on one issue at a time, on its own branch. Agent Code Review shows you the diff, the evidence and a walkthrough before anything becomes a pull request.

Overview

How the loop works

Each app owns one step. The agent writes the code, and a person decides what gets published and merged.

StepAppWhat happens
1. PlanTask Planner (its window is titled Task Explorer)You describe the work or fill in a template. An agent drafts epics and tasks, each with acceptance criteria and a developer persona. You edit them and create them as issues on GitHub or Jira.
2. ImplementTask ImplementerYou pick an issue and click Start Agent. The agent creates a branch (codex/<task-key> by default), implements and tests the task, commits and pushes. It does not open a pull request.
3. ReviewAgent Code Review (PR Review Theater)You read the diff, ask for changes in plain language, check the evidence and take an agent-led walkthrough of the changed behavior.
4. PublishAgent Code Review, Pull Request tabYou check the description and click Create PR, as a draft if you like, then watch CI from the same window.
5. MergeGitHubThe author merges on GitHub. RobOS has no merge button.

Choose your guide

Both guides use the same three apps. The team guide adds shared review defaults, picking up assigned work, and reviewing someone else's pull request.

Building on your own →You plan, implement, review and merge. Set up one repository and take a task all the way to a merged PR. Building as a team →A lead plans, developers implement and review their own branches, and a teammate approves the PR before it merges.

What you need

RobOS does not ship a model. It runs the coding agent you already use, with your own sign-in.

You needUsed by
RobOS, installed or run from a clone. See Get started.All steps
Your agent, installed, signed in and set as active in RobOS AgentsPlanning, implementing, and the review window's chat, evidence and walkthrough
The GitHub CLI, gh, signed inCreating and listing issues, reading the diff, creating the pull request, reading CI and submitting reviews
A task server: a GitHub repository or a Jira projectTask Planner and Task Implementer. The review and pull request steps need the code on GitHub.
A local clone of the repository, with origin on GitHubTask Implementer and the review window

Which agent each app runs

RobOS Agents lists every agent RobOS can drive, and other apps' quick AI requests use the one you set as active. Some apps in this loop call a specific agent CLI instead. Install and sign in to the ones for the apps you use:

AppAgent CLI it runs today
Task Planner, Generate with AIGitHub Copilot, through gh copilot
Task Implementer, Start Agent and Generate PlanThe agent chosen in <robos-agent-selector>: Codex (codex), AGY (agy), Claude Code (claude) or GitHub Copilot (copilot)
Review window: Suggest changes, Edit with agent, evidence, walkthrough and Get CI back to greenCodex, codex. Without it, those features have no agent to run.
Dev Central, Design and ImplementCodex by default, or Claude Code when configured

Read this before you start an agent. Task Implementer runs the agent as your user with permission prompts turned off. The agent can read and write files and run commands without asking, and the app does not create a sandbox. Use it only on repositories and machines where that is acceptable.
