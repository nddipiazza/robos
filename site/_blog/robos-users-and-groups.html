What are RobOS users and groups?

A RobOS user is a person who uses your RobOS machines: you, your partner, your kids, a roommate. Each one has a small profile file with a name, a nickname, an email address, a birthday, a job, hobbies, music they like or can't stand, a gamer tag, and so on. A RobOS group is a named set of those people: Family, Household, Kids, Game Night, a book club.

Why would a household care? Because lots of everyday questions are really questions about people. "What's Jordan's email?" "Who is in the book club?" "Send this to everyone in the family." "Who am I logged in as right now?" Before this change, the answers lived in several RobOS apps that each kept their own idea of who is who. Now there is one list, and everything that needs to know about people (the command line, AI agents, and the Voice Assistant) reads and writes that same list. Change it in one place and every other place sees the change.

Before you start. All of this lives in plain JSON files in your own home folder, under ~/.config/robos/. Nothing is sent anywhere unless you run the sync command and name a machine to sync to. To follow along you only need a RobOS source checkout and Node.js.

Where the data lives

The new library, packages/robos-lib/users-groups.js, sits on top of the existing people store (people-store.js) that the People Directory already used. It works with these files:

  • ~/.config/robos/people/<uid>.json: one file per user. The uid is the name turned into a slug, so "Jordan Lee" becomes jordan-lee.
  • ~/.config/robos/groups/<id>.json: one file per group, with a members list of user ids.
  • ~/.config/robos/settings.json (myProfileUid) and active-voice-context.json: who the active user on this machine is.
  • ~/.config/robos/search-index/people.txt and groups.txt, a Knowledge Graph file at kgraph/users-groups.jsonld, and services/data/users-groups.json for RobOS Services. These three are rebuilt after every change.

There are two kinds of group. A group with its own file is an explicit group. A user's profile can also carry free-form group tags, such as "groups": ["Weekend Crew"]. When no file matches a tag, RobOS shows it as a derived group, built from every profile that carries the tag. robos-groups list --explicit-only leaves the derived ones out.

The two CLIs

packages/robos-cli/robos-users and packages/robos-cli/robos-groups are thin wrappers around the library. Each prints a plain-English answer by default and the full result with --json. For this post we pointed HOME at an empty temporary folder, so nothing touched a real household's files, and created three example people:

$ export HOME=$(mktemp -d) $ robos-users add "Alex Rivera" --email alex@example.com --nickname Alex --role "Science Teacher" \ --groups "Weekend Crew,Book Club" --gamer-tag "AlexTheBold" Added RobOS user Alex Rivera (alex@example.com) in Weekend Crew, Book Club. $ robos-users add "Jordan Lee" --email jordan@example.com --nickname Jordy --role "Nurse" \ --groups "Weekend Crew" --gamer-tag "JordyPlays" Added RobOS user Jordan Lee (jordan@example.com) in Weekend Crew. $ robos-users add "Sam Carter" --email sam@example.com --nickname Sam --role "Systems Engineer" --groups "Book Club" Added RobOS user Sam Carter (sam@example.com) in Book Club. $ robos-users update "Jordy" --birthday 1990-04-12 --hobby "Rock climbing" Updated RobOS user Jordan Lee. $ robos-users list --group "Weekend Crew" RobOS Users (2): • Alex Rivera <alex@example.com> — Science Teacher [Weekend Crew, Book Club] • Jordan Lee ("Jordy") <jordan@example.com> — Nurse [Weekend Crew] $ robos-users switch "Alex" Switched the active RobOS user to Alex Rivera. $ robos-users whoami The active RobOS user is Alex Rivera (Alex), alex@example.com. $ robos-users ask "Jordy" birthday Jordan Lee's birthday is 1990-04-12. $ robos-users ask "Alex" gamerTag Alex's gamer tag is AlexTheBold.

(The CLI also starts each user line with the person's avatar. We left that character out above.)

Look-ups are forgiving. resolveUser() checks the uid, email, username, nickname, first name, display name and gamer tag for an exact match first. If nothing matches, it accepts a first name or nickname that starts with what you typed (three letters or more), then any part of the display name. That is why "Jordy" finds Jordan Lee. ask knows these topics: summary, email, phone, birthday, age, role, gamerTag, rpg, music, music-dislikes, books, hobbies, pet-peeves, personality, games, family and groups.

Two-way group membership

Membership is written down in two places: the group file's members list and each person's groups tags. If those two drift apart, one app says Sam is in the band and another says he isn't. So addMemberToGroup(), removeMemberFromGroup(), createGroup() and deleteGroup() always change both. createUser() and deleteUser() also add and remove the person in any explicit group files they match.

$ robos-groups create "Band Practice" --description "Garage band rehearsal crew" --members "Alex,Sam" Created RobOS group "Band Practice" with 2 members. $ robos-groups emails "Band Practice" Band Practice emails (2): • Alex Rivera <alex@example.com> • Sam Carter <sam@example.com> $ robos-groups user-groups "Sam" Sam Carter belongs to 2 RobOS groups: Band Practice, Book Club. $ robos-groups remove-member "Sam" "Band Practice" Removed Sam Carter from Band Practice. $ robos-groups user-groups "Sam" Sam Carter belongs to 1 RobOS group: Book Club. $ robos-groups list --explicit-only RobOS Groups (1): • Band Practice [band-practice] (1 member) — Garage band rehearsal crew

A voice command later added Jordan to the same group (see the next section). Both files changed together:

# ~/.config/robos/groups/band-practice.json { "id": "band-practice", "name": "Band Practice", "description": "Garage band rehearsal crew", "members": ["alex-rivera", "jordan-lee"], "contexts": [], "settings": {}, "workspaces": [] } # ~/.config/robos/people/jordan-lee.json (excerpt) { "uid": "jordan-lee", "groups": ["Weekend Crew", "Band Practice"], ... }

Two things we noticed while testing. First, on any machine, even an empty test folder, the people store creates the machine owner's two default profiles the first time it loads. They show up in lists and in derived groups: our full robos-groups list showed 8 groups, and 5 of them came only from those two default profiles. We cut them from the output above. Second, add --role fills in both the job title and the relationship field, so show prints the role twice (Role: Nurse · Nurse).

Voice Assistant commands

The Voice Assistant gets two new skills, robos-users and robos-groups. They are listed in skills-executor.js and in the command catalog in voice-commands-registry.js, in a new "People & Groups" category. The executor now asks isUsersOrGroupsVoiceCommand() about each phrase. If the answer is yes, it hands the phrase to executeVoiceCommand() and returns the spoken reply. All of this runs locally with no AI model call.

The hard part is not stealing other skills' phrases. "Add dentist appointment to family calendar" mentions family, and "open group manager" mentions group, but neither is about users. The check strips wake words like "Commander", then turns down anything about calendars, appointments, watchlists or shopping lists, anything starting with play, watch or cast, and plain "open ..." app launches. Questions about a person only count when they name a known user. We ran six phrases through the real SkillsExecutor against the test home folder:

"Commander, who am I" -> robos-users: The active RobOS user is Alex Rivera (Alex), alex@example.com. "what is Alex's gamer tag" -> robos-users: Alex's gamer tag is AlexTheBold. "who is in the Weekend Crew group" -> robos-groups: Weekend Crew has 2 members: Alex Rivera, Jordan Lee. "add Jordy to the Band Practice group" -> robos-groups: Added Jordan Lee to Band Practice. "open group manager" -> not a Users/Groups command (left for the next skill) "add dentist appointment on Friday at 3pm to family calendar" -> not a Users/Groups command (left for the next skill)

"Open RobOS users", "open people directory" and "open group manager" now open the People Directory and the Group Manager instead. The same phrases also work from the command line through say, for example robos-users say "what is Jordy's email".

AI skills for every agent

/robos-users and /robos-groups ship as skill files in every place RobOS keeps them: plugins/robos/skills/robos-users/SKILL.md, robos-groups/SKILL.md, and the copies in .agents/skills/ and .github/skills/, plus slash commands for Claude Code, Antigravity and Gemini CLI. Both are added to plugins/robos/plugin.json. The skills tell the agent which CLI command answers which kind of question, so an agent asked "email the book club" can run robos-groups emails "Book Club" instead of guessing addresses.

Knowledge Graph and RobOS Services sync

After every change, the library rebuilds three things. The first is the search index. The second is a JSON-LD Knowledge Graph with one node per person and per group, using oslc:Person/schema:Person types (13 nodes for 5 users and 8 groups in our test folder). The third is the RobOS Services data file. That file holds the active user id, every user and every group, and it is written with file mode 600, so only you can read it:

$ robos-users kgraph Synced 13 Users & Groups Knowledge Graph nodes to $HOME/.config/robos/kgraph/users-groups.jsonld. $ robos-users sync Synced 5 RobOS users and 8 RobOS groups into local RobOS Services ($HOME/.config/robos/services/data/users-groups.json). $ stat -c '%a' $HOME/.config/robos/services/data/users-groups.json 600

robos-users sync --host <machine> (or saying "sync RobOS users and groups to <machine>") copies the same files to another RobOS machine. First it refreshes everything locally. Then it uses ssh with BatchMode=yes, so it never stops to ask for a password, and rsync to copy people/, groups/, the Knowledge Graph, the indexes and the services file. On the other machine it restarts robos-services-users-groups.service if that service exists, and sets myProfileUid only if that machine has none yet. Last, it asks RobOS Services on port 19400 for /users-groups, using that machine's own access token, and reports whether the answer came back. The host name and SSH user are checked against strict patterns before any command runs. We did not run a remote sync for this post. The RobOS Services gateway itself is not in this repository, so the remote check is described here from the code, not from a run.

Tests

packages/robos-lib/users-groups.test.cjs builds a fresh temporary config folder for each test. The tests cover user create, update and delete (including the automatic group file update), nickname look-up, switching the active user, fact questions, two-way group membership, the Knowledge Graph and services file, and the Voice Assistant routing, including the calendar and "open ..." phrases it must leave alone.

$ node --test packages/robos-lib/users-groups.test.cjs ok 1 - users CRUD, nickname lookup, active user switch, and rich Q&A ok 2 - groups CRUD, two-way membership sync, KGraph, and RobOS Services state payload ok 3 - Voice Assistant commands via VoiceCommandsRegistry and SkillsExecutor # tests 3 # pass 3 # fail 0

Try it yourself

These commands use a throwaway home folder, so they never touch your real users and groups. Leave out the first line to work with your real ones.

# from a RobOS checkout; a temp HOME keeps your real ~/.config/robos untouched export HOME=$(mktemp -d) U=./packages/robos-cli/robos-users; G=./packages/robos-cli/robos-groups $U add "Alex Rivera" --email alex@example.com --nickname Alex --groups "Weekend Crew" $U add "Sam Carter" --email sam@example.com --nickname Sam --groups "Book Club" $U switch "Alex" && $U whoami $U ask "Sam" email $G create "Band Practice" --members "Alex,Sam" $G emails "Band Practice" $G remove-member "Sam" "Band Practice" $G user-groups "Sam" $G say "who is in the Weekend Crew group" $U sync # local RobOS Services file only; add --host <machine> to copy over SSH $U --help; $G --help # unit tests node --test packages/robos-lib/users-groups.test.cjs
